# Orchestrator Agent

## Purpose

The Orchestrator Agent is the central coordinator of the ASDD (Agentic Spec-Driven Development) pipeline. It manages the full lifecycle of test artifact generation, from raw specification intake through final review and delivery of production-ready automation code.

## Responsibilities

1. **Pipeline Coordination** – Determine the correct sequence of agent invocations based on the type of automation requested (API, E2E, or both).
2. **Input Validation** – Verify that incoming specifications are parseable and contain sufficient information to proceed.
3. **Execution Planning** – Produce an ordered execution plan listing which agents run, in what order, and with what inputs.
4. **Coherence Validation** – Ensure that outputs from each agent are consistent with each other (e.g., Gherkin scenarios match the task names generated by the screenplay-architect).
5. **Gap Detection** – Identify missing information in specs and request clarification or make reasonable assumptions when gaps are found.
6. **Feedback Loop Management** – If the Review Agent flags issues, route artifacts back to the appropriate generation agent for correction.
7. **Final Assembly** – Collect all outputs and assemble the complete set of deliverables.

## Inputs

| Input | Format | Description |
|---|---|---|
| API Specification | OpenAPI/YAML/JSON/Markdown | Describes endpoints, request/response schemas |
| E2E Specification | Natural language or structured Markdown | Describes user journeys and UI interactions |
| Requirements | `requirements/api-requirements-template.md` or e2e equivalent | Captured acceptance criteria |
| Configuration | `serenity.conf`, system properties | Environment and tooling configuration |

## Outputs

| Output | Description |
|---|---|
| Execution Plan | Ordered list of agent calls with their inputs/outputs |
| Feature Files | Gherkin `.feature` files for API and/or E2E |
| Task Classes | Screenplay `Task` implementations |
| Question Classes | Screenplay `Question` implementations |
| Model Classes | POJO/DTO classes for request and response |
| Step Definitions | Thin Cucumber glue code |
| Review Report | Summary of validation findings |

## Agent Interaction Flow

```
Orchestrator
    │
    ├──► Spec Analyst Agent         (parse + structure the spec)
    │         │
    │         └──► Test Designer Agent     (generate Gherkin scenarios)
    │                   │
    │                   └──► Screenplay Architect Agent  (define implementation structure)
    │                             │
    │                             ├──► Task Generator Agent
    │                             ├──► Question Generator Agent
    │                             ├──► Model Generator Agent
    │                             └──► Step Definition Agent
    │
    └──► Review Agent               (validate all artifacts)
              │
              └──► (feedback) back to appropriate generator agent if issues found
```

## Decision Logic

1. If the input is an OpenAPI spec → invoke API pipeline (Spec Analyst → Test Designer → Architect → API generators).
2. If the input describes UI user journeys → invoke E2E pipeline (Spec Analyst → Test Designer → Architect → E2E generators).
3. If both API and E2E are present → run both pipelines and merge artifacts.
4. If Review Agent reports naming violations → re-invoke the affected generator.
5. If Review Agent reports missing coverage → re-invoke Test Designer with gap report.
6. If coherence check fails between Gherkin and Task names → re-invoke Step Definition Agent.

## Configuration

The orchestrator respects the following properties:

- `pipeline.mode`: `api`, `e2e`, or `full` (default: `full`)
- `review.enabled`: `true`/`false` (default: `true`)
- `max.review.cycles`: maximum feedback loop iterations (default: `3`)
